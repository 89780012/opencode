# 需求面板编辑与持久化

## 目标

把工作台“设计面板”中的需求理解区域从只读展示改造成可维护的需求清单。用户可以补充新需求、修改已有需求并保存，保存结果由后端持久化，并在再次打开工作台时恢复。

## 背景

- 入口组件为 `packages/strategy-front/src/components/workbench/workbench.tsx`。
- 当前界面在“设计面板”页签展示编号需求列表。
- 列表实际取自当前选中会话的 `requirements` 字段，而不是工作区级静态配置。
- 后端已有 `workspace_requirements` 表，以 `(workspace_path, session_id)` 为主键保存有序字符串数组；创建会话时写入，列出会话时读取。
- 当前缺口是已创建会话没有可用的需求更新接口，前端需求区域也只有只读展示。
- 本次改造同时覆盖前端交互、后端接口和持久化，不接受仅保存在浏览器内存或本地缓存中的实现。

## 需求

- R1：在现有需求理解区域提供新增需求的入口。
- R2：允许修改现有需求的文本内容。
- R3：允许逐条删除需求，并允许将当前会话的需求清单清空后保存。
- R4：允许显式保存变更，并向用户反馈保存中、保存成功和保存失败状态。
- R5：保存动作必须调用后端，并按“工作区 + 当前选中会话”持久化需求数据，不影响同一工作区的其他会话。
- R6：进入或重新打开对应工作台时，前端通过已有会话加载链路读取最新需求，并保持稳定的展示顺序。
- R7：编辑过程不得破坏现有设计面板、对话列表及策略工作流的既有行为。
- R8：前后端数据必须经过现有项目采用的类型和输入校验机制，不通过前端类型断言掩盖契约差异。

## 验收标准

- [x] AC1：用户可在需求理解区域新增一条非空需求，保存后该条目出现在有序列表中。
- [x] AC2：用户可修改任意已有需求，保存后刷新或重新进入页面仍显示修改后的内容。
- [x] AC3：用户可删除任意单条需求；删除全部条目后可将空清单保存并在重新进入时保持为空。
- [x] AC4：一次保存可持久化当前完整需求清单，不追加旧条目、不生成意外重复项或改变顺序。
- [x] AC5：只包含空白字符的单条需求不会被提交；合法的空数组可以提交，前后端均按同一规则校验。
- [x] AC6：保存期间有明确状态且不会重复提交；失败时保留未保存内容并允许重试。
- [x] AC7：无已保存数据或保存后的空清单显示为空状态，不导致面板崩溃。
- [x] AC8：相关前端、后端测试通过，两个受影响包均通过包内类型检查。

## 范围外

- 需求的多人实时协同编辑。
- 需求版本历史、差异对比与回滚。
- 富文本、附件、评论和审批流。
- 需求拖拽排序、自动保存，以及保存后自动重新执行需求识别、策略分析或流程图生成。

## 产品决定

- 需求编辑只作用于当前选中的会话，不在工作区内跨会话共享或覆盖。
- 支持逐条删除，并允许把需求清单清空后保存。
- 保存采用显式提交；单条需求会去除首尾空白，重复文本保持原样和原顺序，不做隐式合并。
