# JS Strategy

这个 skill 负责 JavaScript 策略项目的语言和模板专项能力。
它不重复主 agent 的通用职责，但除了编写代码，还负责运行、调试和输出结果。

当工作区主要由 JavaScript 驱动，或需要修改前端面板、构建脚本、浏览器侧逻辑、Node 侧入口时，使用这个 skill。

进入项目后的第一步：

- 先加载并阅读项目的 `README.md`
- 先从 `README.md` 理解项目目标、运行方式、脚本入口、依赖前提和验证方式
- 如果 `README.md` 与代码现状不一致，同时记录文档描述和实际实现之间的差异

重点关注：

- `package.json` 中的脚本、依赖和工作区身份
- JavaScript 入口文件和前端启动路径
- 构建脚本、打包配置和产物目录
- 当前模板是否已有可复用的状态管理、工具函数和 UI 结构

默认原则：

- 优先沿用现有脚本和构建链路
- 优先补到现有模块，不无故增加新的抽象层
- 修改前先确认哪些文件是源码，哪些更像生成产物
- 如果项目已有面板或页面，优先保持原有结构与交互方式一致
- 不要把任务停留在“代码已修改”；能运行就运行，能调试就调试，能给出结果就给出结果

运行时优先：

- 优先复用项目已有的启动、构建、预览、测试和调试命令
- 先确认入口命令、环境变量和依赖前提，再执行运行验证
- 如果任务包含页面、面板或脚本行为变更，优先实际运行一次相关链路

调试时优先：

- 先复现问题，再定位入口、脚本、资源引用、构建链路或运行日志
- 优先根据现有报错、控制台输出和脚本输出来修正，而不是盲改
- 如果首次修复后仍有问题，继续执行“复现 -> 修复 -> 运行 -> 再观察”

验证时优先：

- 检查脚本命令是否仍然成立
- 检查入口路径、构建路径和资源引用是否被破坏
- 检查新增配置是否与现有模板约定一致

输出结果时至少说明：

- 改动了什么
- 实际运行了哪些命令或链路
- 调试中看到了什么关键结果
- 当前是否已经跑通；如果没有，阻塞点是什么

这个 skill 不负责 SmartX SDK 领域规则；相关约束由 `strategy-service` skill 提供。
