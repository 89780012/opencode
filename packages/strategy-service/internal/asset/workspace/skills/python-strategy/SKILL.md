# Python Strategy

这个 skill 负责 Python 策略项目的语言和模板专项能力。
它不重复主 agent 的通用职责，但除了编写代码，还负责运行、调试和输出结果。

当工作区主要由 Python 驱动，或需要修改策略入口、配置加载、模块组织、运行脚本时，使用这个 skill。

进入项目后的第一步：

- 先加载并阅读项目的 `README.md`
- 先从 `README.md` 理解项目目标、运行方式、依赖前提、入口说明和验证方式
- 如果 `README.md` 与代码现状不一致，同时记录文档描述和实际实现之间的差异

重点关注：

- Python 入口文件和执行路径
- 依赖声明与环境约定
- 配置文件、参数文件和数据文件的位置
- 现有模块划分是否已经承载策略、状态和执行逻辑

默认原则：

- 优先在现有结构内扩展
- 优先复用已有模块、配置和脚本
- 新增文件前先确认是否真的需要新的抽象层
- 参数、阈值和策略配置优先放到独立配置，而不是散落硬编码
- 不要把任务停留在“代码已修改”；能运行就运行，能调试就调试，能给出结果就给出结果

运行时优先：

- 优先复用项目已有的启动、测试、验证和调试命令
- 先确认入口、依赖、配置路径和运行前提，再执行运行验证
- 如果任务涉及策略入口、配置加载或执行链路，优先实际跑通一次相关流程

调试时优先：

- 先复现问题，再定位入口、依赖、配置、模块加载或运行日志
- 优先根据真实报错和运行输出来修正，而不是凭猜测修改
- 如果首次修复后仍有问题，继续执行“复现 -> 修复 -> 运行 -> 再观察”

验证时优先：

- 检查入口是否仍能正确加载
- 检查配置读取路径和依赖声明是否一致
- 检查新增模块是否与当前执行链路匹配

输出结果时至少说明：

- 改动了什么
- 实际运行了哪些命令或链路
- 调试中看到了什么关键结果
- 当前是否已经跑通；如果没有，阻塞点是什么

这个 skill 不负责 SmartX SDK 领域规则；相关约束由 `strategy-service` skill 提供。
