# 回测策略约定

## 本地证据

先加载 `smartx-develop`。只在其 `references/pythonApi.md` 中读取本次需要的章节：

| 能力 | 本地章节 |
| --- | --- |
| 生命周期 | `on_init`、`on_close` |
| Bar 行情 | `subscribe_bar`、`unsubscribe_bar`、`Bar` |
| 委托 | `insert_order`、`PriceType`、`Side`、`Offset`、`BusinessType` |
| 回报 | `account.on_order`、`account.on_trade` |

`demo.py` 只使用这组已记录接口。需求需要持仓、撤单、历史数据或其他事件时，必须先读取对应本地章节；找不到依据时明确写“本地文档未覆盖”，不要套用其他交易框架的 API。

## `demo.py` 的边界

示例演示以下结构：

1. 在 `smart.on_init` 回调中注册订单与成交回报。
2. 订阅两个标的的 1 分钟 Bar，并为每个标的独立计数。
3. 每个标的收到第 100 根 Bar 时提交一次演示买单。
4. 关闭时取消订阅。

它不是完整交易策略：没有入场理论、卖出信号、仓位上限、止损止盈、交易时段过滤或组合级风控。复制或改写前必须按用户需求补齐这些规则，不能把示例成交当成策略有效性的证明。

## 编写规则

- 把账户访问、订阅和下单放在 `init()` 执行后；模块顶层只定义状态、回调并注册生命周期。
- Bar 回调选择一种注册方式。使用 `smart.subscribe_bar(codes, period, callback)` 后，不要再为同一回调注册 `smart.Event.ON_BAR`。
- 按 `bar.code` 保存每个标的的窗口、计数、信号和委托状态，避免两个标的共享计数导致顺序相关结果。
- 只使用当前及过去事件中的数据产生信号；不要读取未来 Bar，也不要用墙钟时间替代 `bar.trading_day`、`bar.start_time` 或 `bar.end_time`。
- 在下单前检查价格、数量、重复信号和已有委托/持仓约束。A 股数量规则、涨跌停、停牌和交易时段若需求涉及，必须从本地证据或用户规则获取。
- 把 `insert_order` 视为委托提交。最终状态以 `on_order` 和 `on_trade` 为准，不把同步返回或提交回调描述为成交。
- 处理 `subscribe_bar` 返回的失败代码。不要在订阅失败后假设全部标的仍有数据。
- 回测回调中避免 `sleep`、无限循环、多进程、交互式输入、运行时安装依赖或无界网络请求。
- 日志只记录定位策略行为所需的有限字段，不输出账号、凭据、完整环境变量或无界行情对象。

## 启动前审阅

- 入口文件和当前 workspace 插件一致。
- 所有 SmartX API、枚举和字段均能在本地 references 中定位。
- 标的代码、Bar 周期、信号窗口和回测配置的行情模式相容。
- 买入、卖出、仓位、重复委托、止损止盈和异常数据行为明确。
- 没有不可达交易分支、重复回调、重复标的赋值或跨标的共享状态。
- 没有把 `smartx_python` 执行成功当作 SmartX 回测成功。

## 结果解释边界

回测报告只能证明策略在本次配置与数据范围内的历史模拟表现。解释时至少同时回显回测区间、初始资金、Bar/快照模式、滑点和费用；不要把高收益、夏普或胜率单独表述为未来保证。策略代码在回测后发生变化时，旧任务结果不能代表当前代码，用户要求验证新代码时必须创建新的回测任务。
